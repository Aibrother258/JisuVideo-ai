## 0. 一句话摘要

shuohao-skills 最值得借鉴的不是"某个 skill 的产出格式"，而是它的**五条工程方法**：① 模型只填结构化数据、脚本管一切确定性计算；② 流程分阶段 + 每阶段一个"必须过门"的校验；③ 上游事实用 seed 确定性搬运、不让模型重新想；④ 批量产出的协议（区间 + 锚点）；⑤ 质量门全部代码化并带击穿用例，且记录"哪道门最常响"反哺规则措辞。这些方法与净化主线的**净化执行、上下文分集、模板资产化**三块都能对接，其中与主线粘合度最高的候选亮点见 §5。

## 1. 梳理口径（借鉴什么 / 不借鉴什么）

| 口径 | 说明 |
| --- | --- |
| 借鉴层级 | 迁移**方法论与数据契约**（规则清单、JSON 结构、校验思想、流程门），不复制 shuohao 的 CLI / SKILL.md / 子代理会话协议 |
| 借鉴边界 | 净化稿是**在线服务内一次调用**完成净化与分集建议；shuohao 是**离线可多轮、可并发子代理**的创作会话。凡依赖多轮/并发/长会话的机制只能借鉴其"协议思想"，落地形态必须在单次调用内收敛 |
| 许可证 | Apache-2.0（技能规则借鉴不影响代码归属；商业化分发按既有结合分析结论处理，不展开） |
| 与既有文档关系 | 根目录 `JisuVideo-ai与shuohao-skills结合分析报告.md` 面向"五件套导入"大整合（已转独立立项）；本文只面向**净化主线**，范围更窄、更落地 |
| 术语 | "门"= shuohao 里由脚本确定性执行的校验项；"质量门"= 一组门 |

## 3. 可借鉴点全景（分组梳理）

> 编号 P1–P16 供 §5 引用。每条给出：shuohao 原文机制 → 净化主线可借鉴形态。

### 3.1 净化执行侧（净化稿 §4 直接相关）

**P1 · 章节目录识别启发式（novel-outline Step1）**
- shuohao：材料优先级写死——用户点名精读章节 > 章节目录+简介 > 分卷摘要；落地是 `chunk` 脚本"按章节标题分卷，识别不出章节就按字数切"。
- 借鉴：净化模板的确定性预清理应内置两套识别——**标题行识别**（`第X章/第X回/第X集` 等正则）与**兜底分块**（无标题行时按字数/段落边界切，用于分段与进度显示）。前者净化稿 §6 已内化。
- 待补细节（建议植入候选）：识别不出章节时的**行为显式化**（shuohao 是打印 `truncated: true` 告知用户，不静默截断）→ 净化对"结构扫描不完整"的源文应给出提示而非闷头删除，防止误删正文段。

**P2 · 删除必须有证据、证据保持原文（novel-outline / novel-characters）**
- shuohao：`volume-pass.md` 要求 `beatMaterial.evidence` **逐字复制原文片段**；`outline-pass.md` 要求关键取舍附 `evidence`；characters 的 validate 会拿原文文件做**引文逐字比对**（校验"引文是否逐字"）。
- 借鉴：净化返回的 `removed: [{ category, snippet }]` 中 `snippet` 必须是**原文逐字**（净化稿 4.3 已定义）；建议把"逐字校验"提为质量门——后端可对 removed.snippet 逐一断言"该片段确实存在于原文、且净化后正文确实少了它"，杜绝模型**改写式"净化"**（例如把病句顺手改顺）。这是"正文不改写"硬边界（净化稿 §3 边界 2）的机器化。

**P3 · 删除类别是模板参数而非写死（novel-outline params.thresholds）**
- shuohao：阈值全部参数化（`params.thresholds`），"平台不同就覆盖，别改代码"。
- 借鉴：净化删除类别清单应**随模板携带**（`source-cleaner-*.md` 模板内声明删什么），而非后端写死类别枚举；模板切换 = 类别清单切换。净化稿 §4.2/§9 已内化此形态。

### 3.2 上下文分集侧（净化稿 §5 直接相关）

**P4 · 分卷摘要脚手架：确定性分卷 → 逐卷摘要 → 下游只见摘要不见原文（novel-outline Step2）**
- shuohao：`chunk` 按章分卷（每卷 15 章）→ 每卷一个子代理产出 `summary-NN.json`（plotlines/characters/beatMaterial/settings）→ 骨架作者**看不到原文，只看摘要**。摘要要求"线索必须落在纸面上，不能指望再翻书"。
- 借鉴：净化稿 5.3 已内化"分卷摘要+段索引喂 episode_planner"。可借鉴的深化点是**摘要字段结构**：shuohao 摘要按"线"（plotlines）不按章组织，且 beatMaterial 记录**爽点素材 moment + type + evidence**。对分集定界而言，喂给 planner 的卷摘要若含"该卷发生了哪些可成集的剧情单元（事件的起讫）"，段界建议会比纯 summary 更准。属 §5 候选。

**P5 · 快版骨架 → 用户拍板 → 细版（novel-outline Step3–4，两轮规则）**
- shuohao：骨架必须跑两轮；第一轮四块填齐、过 `validate --stage beats` 就停，把"砍了哪条线、合了哪些人、大爆点落在第几集"三件事摆给用户拍板；不点头不进下一步。理由：**快版便宜，错了只损失一轮骨架，不是 60 集梗概**。
- 借鉴：对应净化稿 D10 的两轮 vs 一轮问题——净化稿默认一轮（标题/摘要/段界同返）。可借鉴的折中形态：**analyze-episodes 首轮只出 recommended_count + 每集段界落点区间**（无标题摘要）供用户在 detail 确认结构，二次确认后再补标题与摘要草稿？→ 该形态与现状"从 plan 建集"状态机冲突（建集即落草稿），风险高。列为 §5 低优先候选，仅作"段界草案可读"参考，不改一轮默认。

**P6 · 分批产出的协议：每批区间 + 本批锚点，批间靠骨架对齐（novel-outline Step5 / novel-script Step0）**
- shuohao：outline 分集每批 ≤10 集、script 每批 ≤3 集；每批子代理拿到"自己负责的集数区间 + 区间内落着的爽点"；**批与批之间靠骨架和爽点表对齐，不靠上一批的原文**。
- 借鉴：净化稿 5.3 已记录"后续分批借鉴其区间+锚点协议"。对净化主线的现实含义：若未来"分析→确认→生成"解耦，重生成的批次应携带**上一轮已拍板的段界/标题为骨架**（锚点），避免批间漂移——对应 episode_plan_drafts 审阅流后续增强。

**P7 · seed 确定性搬运：上游事实不让模型重新想（novel-script/novel-art/novel-storyboard 的 seed 命令）**
- shuohao：seed 把上游已拍板的事实（目标秒数、钩子、悬念、爽点认领、场景人物清单）**脚本化搬进底稿**，`scenes`/`shots` 留空才是模型该写的；"这些事实不要让模型重新想一遍"。
- 借鉴：`analyze-episodes` 的入参构造已是同类思想（段索引+摘要注入、不注入全文，5.2）。深化候选：把 `recommended_count`（defaultEpisodeCount 预算）与**确定性段摘要**作为 seed 块与 AI 建议并列返回，后端 diff"AI 改了哪些 seed 段界"→ 只对差异做自然边界对齐，可降低 AI 越界概率（越界时 fallback 到 seed 值而非全文等分）。

**P8 · 时长/容量预算是墙，超出先砍、写欠不注水（novel-script）**
- shuohao：目标秒数是硬约束；台词按 4.5 字/秒、动作按 2.5 秒/拍确定性折算，写完 validate 看数；"写超先砍动作节拍，写欠补冲突不补寒暄"。
- 借鉴：净化侧对应**段落长度预算**——每段过长/过短的检测门槛可作为净化质量门（例如"单段 > 阈值可能是漏删的卷前语/公告"），辅助 removed 之外漏网杂质的兜底提示。属 §5 候选（与 P10 合并评估）。

### 3.3 模板 / 规则资产化侧（净化稿 §4.1/§9 设置页相关）

**P9 · 规则措辞分层：主干给行为、references 按需加载细节（shuohao 仓库结构）**
- shuohao：每个 skill 目录 = SKILL.md（给 agent 的主干行为）+ references/（按需加载的详细指令，如 pass 文档）+ scripts/（确定性工具）+ examples/（样例即夹具）。
- 借鉴：净化模板可同构——`source-cleaner-*.md` 只放"行为主干 + 删除类别 + 保留类别"（用户可编辑的最小面），识别正则与质量门阈值放后端内置资产（不进用户可编辑模板，防误改）。设置页"净化模板"管理的是**类别清单与说明文字**，而非正则本体 → 降低用户编辑面同时保持模板可扩展。**建议植入候选。**

**P10 · 质量门代码化 + 每门带击穿用例（五个 skill 共 14+10+11+17 道门）**
- shuohao：质量门"全部是代码，不是给你读的清单"；`validate` 逐条查，违规逐条修、改完重跑直到通过；每个 selftest 断言数 154–355，**每道门都有击穿用例证明它真的会拦**。
- 借鉴（净化主线最大的一块可移植资产）：
  - 净化结果质量门（后端确定性检查）：① removed.snippet 逐字存在于原文；② 净化后正文不含任何模板声明删除的标题行/水印残留（正则复查）；③ 净化后正文 = 原文去掉全部 removed 片段后的连续结果（**不漏字不重字**的机器证明，替代人工抽查）；④ 无单段异常膨胀。
  - 段界质量门：para_start/end 单调、有界、不重叠、覆盖全集（净化稿 5.4 normalizeEpisodePlan 已列，可补"段落摘要必须能对回原文段"逐字/包含校验）。
  - 测试资产：每道门一条**击穿用例**（构造"净化后仍残留水印"→ 门必须响），与净化稿 §8 验收 7 的"新增净化/锚点切片用例"衔接。
  - 属 §5 头号候选。

**P11 · 体检模式：贴产物只跑门给诊断，未过的门不阻断展示（novel-outline checkup）**
- shuohao：checkup 对现成 outline.json 只输出 14 道门 ✓/✗；未过的门**不阻止渲染**——"要的就是把病灶摆出来看"。
- 借鉴：detail 页"重新净化"前可加**净化体检**——对当前 clean_text 跑规则复查（不进新的 AI 调用），把"疑似残留标题行/水印/异常段"列出供用户决定是否重净，替代盲目重跑消耗额度。与净化稿 5.5"换模板重新净化"衔接为低成本前置。**建议植入候选。**

**P12 · 门失败累积 stats：哪道门最常响 → 改的是规则措辞（novel-storyboard 的 .gates.jsonl + stats）**
- shuohao：validate/checkup 每次把门结果追加 `.gates.jsonl`，`stats` 回答三件事——哪道门最常响（那条规则模型最常无视，**该改的是措辞**）、哪道门从没响过（死门或规则已被内化）、失败详情长什么样。**CLAUDE.md 特意标注"只在 novel-storyboard 试点，验证 stats 真的指向该改的规则再推广，不主动复制到其余五个"**——这是"先验证再推广"的工程自律。
- 借鉴：净化模板迭代的闭环——记录每次净化的 removed 类别分布与"模板重跑后用户手动补回/改动的片段"，回答"哪个类别删过头（用户总补回）、哪个类别永远不命中（死规则）"，反哺模板类别措辞。落地形态可轻可重：轻 = 每次 clean-source 落一行审计日志（category 计数）；重 = 结构化到 dashboard。**建议植入候选（轻量版）。**

### 3.4 工程方法侧（通用，跨净化/分集）

**P13 · 流程门分阶段：skeleton→beats→full（novel-outline validate --stage）**
- shuohao：stage 即流程门——骨架拍板前过 skeleton、写分集前必过 beats（爽点间隔错了分集写完全废）、交付前过 full。
- 借鉴：净化主线的流程门可对应为"净化结果门（P10）→ 段界合法性门（进 plan 草稿前）"两档，不允许跳过中间的确定性检查直接建集——与净化稿 §5.4"建集唯一入口 episode_plan_drafts → from-plan"叠加后，等于给状态机入口加一道机器门。

**P14 · 联动校验点名断链，不靠记忆（novel-outline 联动更新）**
- shuohao：用户改了上游就跑 validate，报错点名下游哪里断（合并人物后哪些集引用被删 ID、砍场景后哪些集空转）——"不要靠记忆提示联动，靠校验器"。
- 借鉴：净化后内容变化会触发 detail 既有 stale 守卫（5.5 已内化"全文已变化需重新生成"）；可借鉴的深化点是**点名差异位置**：重净化后向用户展示"本次净化相比上一版删改了哪几处 + 这会影响哪些集的分集建议"，而不是笼统的"内容已变化，需重新生成"。

**P15 · 断点续跑 / 分段进度透明（novel-characters Step6/Step8）**
- shuohao：`card-<slug>.json` 已存在的角色不重跑；失败重来只补缺的。净化超长分段时（净化稿 §4.1 "第 x/y 段"进度）同思路。
- 借鉴：`clean-source` 超长分段净化若中段失败，**已完成的段缓存、重试只补失败段**（而非整篇重跑）——净化稿 D6 已定"自动分段跑完拼接"，补一个失败段级重试即可，成本低。

**P16 · 常见病清单（novel-script "常见病"表）**
- shuohao：把最常犯的错写成"病→症状→治法"表（广播剧/文学病/开场死画面/注水/演讲癖/全知病/断头戏），作为写作手感规则的沉淀物。
- 借鉴：净化模板可附"净化常见病"（把正文当备注删了、把对话括号内容当元信息删了、漏删卷前语、误删章节过渡句），随模板分发给模型作为负例——提升模板即提示词的质量。低成本，随 P9 模板结构一并落地。
