# HB-20260901-03：全文导入与分集工作流生产加固

日期：2026-09-01
状态：已完成代码、数据库迁移、全量测试、生产构建与本地开发栈实测
承接复盘：`HB-20260901-02`

## 1. 目标与边界

本轮关闭二次全面复盘发现的全部高优先级问题，使“导入全文 → AI 推荐集数 → 逐集审阅/批注 → 生成或同步到剧集列表”具备可靠的数据边界、恢复能力、并发保护和安全基线。

本轮未调用付费 AI、未生成视频，也没有修改用户现有项目正文。接口实测使用临时项目，验证结束后已清理。

## 2. 问题关闭情况

| 原问题 | 修复结果 |
|---|---|
| 长段落拆分可能丢字 | 按原文字符边界切片；所有集正文顺序拼接后与源全文完全一致 |
| 20 万字符与 MySQL `TEXT` 容量冲突 | 项目正文、元数据及剧集正文相关字段迁移为 `LONGTEXT` |
| URL 导入超限时静默截断 | 超过 200,000 字符明确拒绝，不再截掉尾部 |
| 分集状态仅在浏览器、标记可伪造 | 新增服务端 `episode_plan_drafts`，保存版本、全文哈希、方案指纹、剧集 ID 与修订历史 |
| 多标签并发覆盖、集号重复 | 事务内锁定并校验版本；新增 `(drama_id, episode_number)` 唯一索引；过期版本返回 409 |
| 生成后再次编辑状态不可靠 | “已生成”由服务端指纹与剧集 ID 判断；方案变化后恢复为可同步状态 |
| localStorage 可误判已生成 | 本地存储仅作备份，不能提升服务端状态；跨浏览器可从服务端恢复 |
| 已进入制作的剧集可能被覆盖 | 同步前在事务内检查剧本、分镜等制作进度，存在下游内容时拒绝自动覆盖 |
| URL 导入存在 DNS 重绑定风险 | 固定连接到已验证 IP，保留正确 Host/SNI，连接后复核远端地址；重定向逐跳校验 |
| 正文和批注可能进入日志 | 前后端只记录结构摘要，创作正文、批注和方案内容统一脱敏 |
| AI 接口可被高频并发调用 | 对 AI 路由增加频率与并发保护 |
| 服务默认暴露到局域网 | 前端、后端和 MySQL 端口统一绑定 `127.0.0.1` |
| 缺少统一测试入口和行为测试 | 前端新增 `npm test`，补齐拆分、版本、请求保护、生成状态行为测试，并修复陈旧测试基线 |

## 3. 数据库与服务端设计

### 3.1 长文本迁移

以下字段已迁移为 `LONGTEXT`：

- `dramas.description`
- `dramas.metadata`
- `episodes.content`
- `episodes.script_content`
- `episodes.description`

`episodes` 新增唯一索引 `uq_episodes_drama_number(drama_id, episode_number)`，避免并发创建重复集号。

### 3.2 服务端分集草稿

新表 `episode_plan_drafts` 保存当前全文哈希、方案内容指纹、单调递增的 `version`、稳定的剧集身份、已生成 episode ID、确认状态以及最近 20 次服务端修订。

所有保存、首次生成和再次同步均要求客户端提交 `expected_version`。版本不一致时返回 HTTP 409，并把服务器最新版交给前端处理，防止后写覆盖先写。

### 3.3 生成与同步约束

- 首次生成只使用服务端当前草稿，不信任客户端隐藏元数据。
- 生成前在事务内锁定项目与相关剧集，再检查集号和历史记录。
- 删除过的历史集号也参与冲突检查，避免唯一索引与业务编号含义分裂。
- 同步保留已有 episode ID；实测编辑方案后同步，ID 保持不变。
- 已存在剧本或分镜等制作进度时，自动同步停止并提示人工处理。

## 4. 前端调整

- AI 分集方案生成后立即保存到服务器，并自动保存标题、摘要、原文、批注、确认状态和画面参数。
- 自动保存串行化，保存请求进行期间产生的新编辑不会被旧响应覆盖。
- 刷新页面或更换浏览器后优先恢复服务器草稿；localStorage 仅作为备份。
- 409 冲突时显示明确的版本冲突区，可加载服务器版本继续处理，不静默覆盖。
- 每集标题、摘要、批注及汇总意见均有明确长度限制，超限拒绝保存而不是截断。
- “生成到剧集列表/已生成/同步修改”状态全部来自服务端版本与指纹。

## 5. 安全与运行边界

- URL 导入拒绝回环、私网、链路本地、保留地址和解析异常地址。
- DNS 校验和实际连接使用同一已验证 IP，降低校验后换址攻击风险。
- 创作正文、批注和方案内容不会原样进入请求日志。
- 戏剧路由请求体上限为 2 MB；业务正文上限为 200,000 字符。
- 开发与常规 Compose 端口只监听本机：前端 `3013`、后端 `5679`、MySQL `3307`。
- AI 接口具备速率与并发保护；真实模型质量和额度仍需单独验收。

## 7. 用户操作路径

1. 打开 `http://127.0.0.1:3013/`，进入或新建项目。
2. 粘贴全文、上传 TXT/MD，或填写允许访问的公开小说页面链接。
3. 保存全文与项目参数，点击 AI 推荐集数。
4. 在下方等宽 EP 标签中逐集编辑原文、标题、摘要和批注，并确认。
5. 可汇总批注后重新拆分，也可全部确认后生成到剧集列表。
6. 已生成方案再次修改时按钮切换为同步；另一标签页已修改时页面提示版本冲突。

## 9. 回滚说明

- 应用层可按本轮文件清单回退，但不要直接删除用户已有的 `episode_plan_drafts` 数据。
- `LONGTEXT` 降回 `TEXT` 可能造成数据截断，未检查实际长度前不得回滚字段类型。
- 移除唯一索引或恢复旧同步逻辑会重新引入覆盖和重复集号风险。
- 若 URL 导入出现兼容问题，可暂时关闭 URL 入口并保留粘贴和 TXT/MD 上传，不应放宽私网地址校验。
