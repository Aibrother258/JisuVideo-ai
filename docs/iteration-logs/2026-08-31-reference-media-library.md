# HB-20260831-01：视频生成参考素材本地上传与资产库复用

## 1. 迭代概况

- 日期：2026-08-31
- 状态：已完成，本地开发环境已验证
- 运行环境：Docker 热加载开发栈
- 前端：http://127.0.0.1:3013
- 后端：http://127.0.0.1:5679
- MySQL：宿主机端口 3307
- 影响模块：视频生成工作台、上传接口、素材库、媒体解析、任务日志

本次迭代解决的问题是：分镜视频生成区域原来只能依赖系统已有的绑定素材，用户无法方便地从电脑选择图片、视频或音频，也不能把以前上传或生成过的素材重新加载到当前分镜。迭代后，每一种参考媒体都有“本地上传”和“从资产库选择”两个入口。

## 2. 用户需求

在单集工作台的视频生成区域，将以下三类参考素材改造为双入口：

- 参考图片：可以从本地上传，也可以从资产库选择。
- 参考视频：可以从本地上传，也可以复用已有分镜视频或资产库视频。
- 参考音频：可以从本地上传，也可以从资产库选择。

上传后的文件不能只是一次性临时地址，而应进入当前短剧的素材库，方便后续分镜继续使用。

## 3. 本次范围

- 本地图片、视频、音频可转换为模型可使用的数据地址。
- 每个分镜独立记住已选择的三类参考素材。
- 加入格式、数量、文件大小和模型能力提示。
- 保护日志，避免上传文件内容、Base64 数据和密钥进入运行日志。

### 本次未做

- 没有新增完整的独立素材库管理页面。
- 没有实现素材删除、重命名、收藏和跨短剧复制。
- “某个素材绑定到某个分镜”的选择状态暂未写入 MySQL；当前保存在浏览器本地存储中。
- 当前 AutoDL H3 工作流不接收参考视频，因此参考视频只对其他支持该参数的厂商开放。

## 4. 关键设计决策

### 4.1 资产本体与分镜选择状态分离

上传文件本身持久化到服务器存储，并在 MySQL `assets` 表登记。这样文件在刷新页面后仍然存在，也可以被同一短剧的其他分镜复用。

分镜当前选中了哪些图片、视频和音频，使用以下浏览器键保存：

```text
huobao:video-refs:{dramaId}:{episodeNumber}
```

键下面再按 `storyboard_id` 保存图片、视频和音频 URL 数组。这样切换分镜或刷新页面不会丢失选择，同时不改变现有 `storyboards` 表中 `reference_images` 的旧语义。

这个方案的限制是：同一用户换浏览器、清除浏览器数据或换电脑后，需要重新选择素材。后续若需要多人协作，应新增正式的分镜参考素材关联表。

### 4.2 资产库按短剧复用

查询素材时，优先返回当前短剧素材，并允许短剧内跨集复用。未归属短剧的素材可以作为公共素材返回；其他短剧的私有素材不会混入。

### 4.3 本地媒体传递策略

本地媒体 URL 形如 `/static/...`。当配置了可公开访问的 `PUBLIC_BASE_URL` 时，后端可以转换为完整公网地址；没有公网地址时，图片继续走现有压缩数据地址逻辑，视频与音频读取为正确 MIME 类型的 Base64 Data URL。

这保证本机模型或支持 Data URL 的接口可以直接使用本地素材，但大型视频转 Base64 会增加请求体积。需要公网远端服务时，长期方案仍应是对象存储或短期签名 URL。

## 5. 前端改动

主要文件：`frontend/app/views/drama/episode.vue`、`frontend/app/composables/useApi.ts`。

### 5.1 视频生成面板

参考媒体区域拆成三行：

| 类型 | 数量限制 | 本地上传 | 资产库来源 |
|---|---:|---|---|
| 图片 | 总计最多 9 张 | JPG、JPEG、PNG、WebP | 角色图、场景图、道具图、上传图片 |
| 视频 | 最多 3 个 | MP4、MOV、WebM、M4V | 已生成分镜视频、上传视频 |
| 音频 | 最多 3 个 | MP3、WAV、M4A、AAC、FLAC | 上传音频 |

图片数量不是简单统计绑定资产条数，而是对真实存在的 URL 做归一化、去重后再统计，避免空图片或重复图片错误占用 9 个槽位。

### 5.2 素材库选择弹窗

弹窗按当前选择类型过滤：

- 图片显示缩略图。
- 视频加载媒体元数据并显示视频预览。
- 音频显示统一音频卡片。
- 已经由分镜角色、场景或道具自动绑定的图片标记为“已绑定”，不能重复添加。
- 手动选择的素材标记为“已选”，再次点击可以取消。

URL 进入选择列表前统一补齐前导 `/`，并通过 `Set` 去重，避免 `static/a.png` 与 `/static/a.png` 被视为两个素材。

### 5.3 上传行为

参考媒体上传时，前端会随文件发送：

```text
save_to_library=1
drama_id
episode_id
storyboard_id
category=reference
```

上传成功后：

1. URL 立即加入当前分镜的选择列表。
2. 素材库重新加载。
3. 当前分镜选择状态写入浏览器本地存储。

## 6. 后端改动

### 6.1 新增素材库接口

新增文件：`backend/src/routes/assets.ts`。

接口：

```http
GET /api/v1/assets?drama_id={id}&episode_id={id}&type=image|video|audio
```

行为：

- 排除 `deleted_at` 不为空的记录。
- 支持按媒体类型过滤。
- 支持当前短剧、当前剧集和公共素材范围过滤。
- 按创建时间倒序返回。

路由在 `backend/src/index.ts` 注册到 `/api/v1/assets`。

### 6.2 上传接口扩展

原有上传地址保持不变：

```http
POST /api/v1/upload/image
POST /api/v1/upload/video
POST /api/v1/upload/audio
```

当 multipart 表单带 `save_to_library=1` 时，上传成功后新增一条 `assets` 记录，保存短剧、剧集、分镜、名称、类型、URL、本地路径、文件大小、MIME、格式和时间等信息，并在响应中返回 `asset_id`。

图片上传继续生成 WebP 缩略图，并把 `thumbnail_url` 写入资产记录。音频新增 FLAC 扩展名和 MIME 支持。

当前限制：

- 参考视频最大 50 MB。
- 参考音频最大 20 MB。
- 视频仅允许 MP4、MOV、WebM、M4V。
- 音频仅允许 MP3、WAV、M4A、AAC、FLAC。

### 6.3 本地视频和音频解析

`backend/src/utils/storage.ts` 新增媒体 MIME 映射和 `readMediaAsDataUrl()`。`backend/src/services/generation.ts` 在解析参考视频、参考音频时执行以下逻辑：

1. 公网 URL 原样使用。
2. 有 `PUBLIC_BASE_URL` 时，把 `/static/...` 转成完整地址。
3. 无公网地址时读取本地文件并生成对应 `data:video/...` 或 `data:audio/...` 地址。

### 6.4 日志保护

- multipart 文件体在请求日志中显示为占位文本，不输出二进制内容。
- 所有 `data:` 地址统一脱敏，避免 Base64 图片、视频或音频进入日志。
- 密钥字段继续走统一脱敏逻辑。

## 7. 模型兼容性

- 通用任务接口仍执行图片最多 9 张、视频最多 3 个、音频最多 3 个的校验。
- 只选择音频而没有任何图片或视频时，前端和后端都会阻止提交。
- 当前 `minimax_h3_image_audio_to_video_v2_15s` AutoDL 工作流接受图片和音频，不接受参考视频。选择 AutoDL 且存在参考视频时，界面明确提示用户移除。
- 参考视频入口仍然保留，用于 Seedance 等支持视频参考的模型。

## 9. 用户操作流程

1. 打开短剧单集工作台。
2. 进入“视频生成”，选择一个分镜。
3. 在“参考图片 / 视频 / 音频”区域选择媒体类型。
4. 点击“本地上传”选择电脑文件，或者点击“从资产库选择”。
5. 在弹窗中点击素材卡片，右上角变为“已选”。
6. 点击“完成”关闭弹窗。
7. 检查图片、视频、音频数量以及当前视频厂商提示。
8. 发起视频生成。

上传素材会长期保留在素材库；当前分镜的选择会在同一浏览器中记住。

## 10. 已知限制与风险

1. 分镜选择关系存在浏览器本地存储，不支持跨浏览器同步。
2. 大型视频转 Base64 会显著扩大请求体，应优先为远端生成服务配置公网对象存储。
3. 当前没有素材删除界面，测试素材需要通过后续素材管理功能或数据库维护清理。
4. `assets` 查询当前在应用层过滤；素材量很大后应改成数据库条件查询并增加索引。
5. 本次只对图片完成了真实上传全链路验证；视频、音频完成了格式校验、接口、数据地址和构建验证，但未分别提交付费视频任务验证所有上游厂商。

## 11. 回滚建议

如需回滚界面功能：

- 移除视频面板的素材库按钮和选择弹窗。
- 移除 `assetLibraryAPI` 和 `/api/v1/assets` 路由。
- 恢复上传接口为只保存文件、不写 `assets`。

不建议删除已经上传的实体文件或 `assets` 记录；保留数据不会影响旧版视频生成，可以在确认无引用后单独清理。

## 12. 后续建议

- 新增 `storyboard_reference_assets` 关联表，正式持久化分镜选择。
- 增加素材库管理页面：搜索、标签、重命名、删除、收藏和批量导入。
- 为视频和音频生成缩略图、波形、时长与编码信息。
- 增加对象存储上传和短期签名 URL，避免大型 Base64 请求。
- 为三类上传接口和素材范围过滤增加自动化测试。
