## 4. P1：修复前不建议正式使用

### P1-01：长句拆分会静默丢失原文

- 位置：`backend/src/services/episode-planning.ts:7`
- 原因：句子正则每次最多匹配 1,200 字，但未锚定当前游标。遇到超过 1,200 字、下一处才有句末标点的内容时，正则会从后方开始匹配，跳过开头。
- 主审实测：输入 1,317 字，要求拆 2 集，输出只保留 1,207 字，开头 110 字消失。
- 影响：用户看到的分集内容已经缺字，确认后会把缺失版本正式写入剧集列表。
- 建议：改为显式游标扫描；任何拆分结果必须通过“去除系统插入分隔符后与规范化原文完全一致”的不变量测试。

### P1-02：20 万字符上限与 MySQL `TEXT` 实际容量不一致

- 位置：`backend/src/db/mysql-schema.ts:7,27`，前端限制见 `frontend/app/pages/index.vue:200` 和 `frontend/app/views/drama/detail.vue:72,266`
- 实际数据库核查：
  - `dramas.description`：`TEXT`，最大 65,535 字节
  - `episodes.content`：`TEXT`，最大 65,535 字节
  - `episodes.description`、`script_content`：同样是 `TEXT`
- 影响：UTF-8 中文通常约 3 字节；约 2.1 万个常用汉字就可能达到单列上限，远低于界面承诺的 20 万字符。严格模式会返回 `Data too long`；宽松模式存在截断风险。
- 建议：先迁移为 `MEDIUMTEXT` 或 `LONGTEXT`，再保留 20 万字符产品上限；迁移前应将界面限制降到按 UTF-8 字节计算的安全值。

### P1-03：超长网页导入静默截断

- 位置：`backend/src/services/source-import.ts:96,110`
- 原因：纯文本和 HTML 抽取都直接 `.slice(0, 200_000)`，仍返回读取成功，没有 `truncated` 标记。
- 影响：用户会把缺少尾部的内容当作“全文”继续分析和保存。
- 建议：超过限制时直接拒绝并提示改用文件/分卷；如果允许截断，必须返回原始长度、截断状态并要求用户明确确认。

### P1-04：安全同步标记可伪造，缺少服务器版本校验

- 位置：`backend/src/routes/dramas.ts:390-445`，可写 metadata 见 `backend/src/routes/dramas.ts:505`
- 原因：覆盖授权依赖项目 metadata 中的 `source: full-text-review-v1`，但 metadata 可由普通项目更新接口原样写入；服务端也没有校验客户端基于哪个服务器版本、原 episode ID 集合或上一版指纹。
- 影响：伪造/遗留标记、旧标签页、删除后补建的同数量 draft 剧集，都可能被按序覆盖。
- 建议：使用服务端管理的不可由普通 PUT 修改的 plan/version 记录；同步请求携带 `base_version`，在事务内做乐观锁比较，并绑定 episode IDs。

### P1-05：小说链接校验存在 DNS 重绑定窗口

- 位置：`backend/src/services/source-import.ts:42,120`
- 原因：代码先用 DNS lookup 验证公网 IP，随后 `fetch(url)` 又按主机名重新解析，没有把已验证 IP 固定到连接。
- 影响：攻击域名可能在两次解析之间切换到本机、云元数据或局域网标准端口，实现 SSRF。
- 建议：使用能够固定已验证 IP 的 HTTP Agent/自定义 lookup，连接后再次核对远端地址；更稳妥的方式是通过带内网阻断的专用出口代理抓取。

## 5. P2：进入稳定生产前应补齐

### P2-01：创建/同步前置检查位于事务外

- 位置：`backend/src/routes/dramas.ts:364-418`
- 两个并发首次提交都可能先看到“无剧集”，然后各插入一套相同集号。
- 同步检查结束后到事务更新前，另一请求可能创建剧本/分镜或改变状态。
- 数据库没有 `(drama_id, episode_number)` 唯一约束，无法在底层阻止重复集号。
- 建议：唯一索引 + 幂等 plan ID + 事务内锁定项目/剧集行并重新检查制作状态。

### P2-02：本地旧指纹会覆盖服务器新指纹

- 位置：`frontend/app/views/drama/detail.vue:1095`
- 页面先从服务器 metadata 读取新指纹，随后恢复 localStorage 时又优先使用旧 `saved.generated_plan_hash`。
- 多标签页或其他客户端同步后，旧页面可能错误显示“已生成”。
- 建议：服务器版本优先；本地草稿记录 `base_server_version`，发现不一致时显示冲突并禁止覆盖。

### P2-03：换浏览器后无法恢复完整审阅方案

- metadata 只保存来源、集数和指纹；标题、摘要、原文、批注和确认状态只在 localStorage。
- 换浏览器后可以识别项目曾生成过，但无法恢复分集审阅区和“已生成”按钮。
- 之前日志中“换浏览器后仍可识别”的表述只对标记成立，不代表完整工作区可恢复。
- 建议：新增服务端 `episode_plan_drafts` 存储，或在已有剧集仍未开工时从剧集列表重建只读方案。

### P2-04：测试以源码正则为主，未覆盖真实状态机

- 位置：`backend/tests/source-import-and-episode-planning.test.mjs:30`、`frontend/tests/full-source-workflow-structure.test.mjs:79`
- 当前测试只能证明代码中存在按钮、字段或字符串，不能证明：
  - localStorage 恢复正确；
  - 服务器指纹优先；
  - 首次生成、修改、再次同步正确；
  - 旧指纹、伪造 metadata、并发提交被拒绝；
  - 超长中文可正确保存；
  - 超过 1,200 字的无标点长句不丢字。
- 建议：增加服务层单测、真实 MySQL 集成测试和 Vue 组件交互测试。

### P2-05：AI 接口缺少调用限流和并发限制

- 位置：`backend/src/routes/dramas.ts:235-355`
- `/analyze-source` 和 `/analyze-episodes` 会直接使用当前模型配置，没有认证、速率或并发限制。
- Docker 将 `5679` 发布到宿主机所有接口；若防火墙允许其他主机访问，第三方客户端可反复消耗模型额度。CORS 不是服务端认证。
- 建议：开发环境至少绑定 `127.0.0.1`；增加本机访问策略、请求限流和同项目单任务互斥。

### P2-06：正文与批注进入明文日志

- 位置：`backend/src/middleware/logger.ts:75`、`frontend/app/composables/useApi.ts:7`
- 前端调试日志打印完整请求 body；后端日志打印 JSON body 前 500 字。脱敏只覆盖密钥，不覆盖 `content`、`episodes` 和 `review_notes`。
- 建议：这些接口只记录字符数、集数和 request ID，禁止记录故事正文、分集内容与批注。

### P2-07：批注预算只限制 note，不限制标题和摘要

- 位置：`backend/src/routes/dramas.ts:310-326`
- note 总量限制为 2 万字，但最多 50 条 title/summary 仍可额外进入模型上下文；批量提交接口也没有合理的标题/摘要长度上限。
- 建议：对整个 review JSON 做统一字节预算，并对批量生成的 title、summary 单独限长。

### P2-08：批注重拆没有版本历史

- 前端在重拆成功后清空当前各集批注，只在 reason 中记录“综合 N 条批注”。
- 用户无法回看 AI 是否逐项落实，也无法比较重拆前后方案。
- 建议：保留 revision history：原方案、批注快照、新方案、模型和时间。

## 7. 上线判断

### 当前可用范围

- 本机单用户。
- 短文本试用，建议全文明显低于 2 万中文字符。
- 不包含超长无标点段落。
- 只做 AI 方案体验和人工复核。
- 不把服务端口开放给局域网或公网。

### 当前不建议范围

- 长篇小说整本导入。
- 将 20 万字符作为可靠保存能力宣传。
- 多标签、多用户、多设备共同编辑。
- 对已进入剧本/分镜阶段的剧集做自动同步。
- 局域网或公网部署。

结论：`CONDITIONAL NO-GO`。界面体验可以继续内部试用，但正式长篇生产应先完成 P1-01、P1-02、P1-03、P1-04；若保留 URL 导入，还必须处理 P1-05。

## 8. 推荐修复顺序

1. 修复拆分器，并建立“全文零丢失”不变量测试。

4. 将分集版本改为服务端正式实体，加入版本号、episode IDs、唯一索引和乐观锁。
5. 把创建/同步检查移入同一事务，并做并发集成测试。
6. 修复 DNS 重绑定，或暂时关闭 URL 导入、只保留粘贴和文件。
7. 正文/批注退出前后端日志，AI 接口增加本机限制、限流和单项目互斥。
8. 补 Vue 交互测试、MySQL 集成测试和前端统一 `npm test` 命令。
9. 最后再做真实 AI 小样验收和一篇中等长度中文小说的全流程验收。
