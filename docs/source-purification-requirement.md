## 1. 现状核对（代码事实，与 v0.1 相同，不再展开）

- 新建向导：`source` 输入（粘贴 / TXT·MD / 链接抓取）→「交给 AI 提炼」（`project_analyzer` 提炼项目名/风格/比例）→ 创建项目（**原文原样**存 `dramas.description`）。
- 分集草稿：详情页 `analyze-episodes`（`episode_planner` 只出集数/标题/摘要），正文由 `splitSourceIntoEpisodes` **按句号等分长度**从原文切片。
- 根因：全文杂质无清理环节 + 等分切片不认原书章/集结构 → "标题、第X集被分进各集正文"。

## 3. 目标链路（v0.2 终态）

```text
【创建向导】
source（粘贴/上传/链接）→【净化正文·新步骤】→ 提炼（project_analyzer）→ 创建项目
                                    │
                   原始全文 + 净化正文 并存入库（dramas.description / dramas.clean_text）
                                    ▼
【详情页分集】AI(episode_planner) 基于净化正文按上下文定集界
              → 后端按锚点最近自然边界切片（不改写）→ episode_plan_drafts（沿用状态机）
```

两条边界必须守住：
1. **跳过净化**（用户直接下一步）→ 行为与现状**完全一致**（净化是可选增量步骤）。
2. **正文不改写、不漏字**：净化只删框架杂质；分集只是切分；切分素材一律来自正文原文（净化正文或原始全文），模型永不重写正文。

## 4. 「净化正文」步骤细化

### 4.1 交互（创建向导第 2 步）
- 进入条件：来源内容 ≥ 20 字，且为叙事剧情类文本（网文/小说/剧本等剧情正文——平台当前产品形态即短剧叙事输入）。纯文稿/口播稿/说明类输入不出现本步骤（无可清理的章/集框架标记）。
- 布局：
  - 顶部：净化模板下拉（默认「通用中文网文净化」，选项来自设置）+「重新净化」按钮。
  - 主区：净化结果 textarea（**可人工编辑**）。
  - 侧栏/折叠区：「本次移除 N 处」清单 —— 每条展示被删原文片段 + 类别（标题行/书名/水印/备注/作者的话…），供用户确认 AI 没删错。
  - 底部操作：`上一步(回到来源)` / `跳过净化` / `下一步：交给 AI 提炼`。
- 状态：净化中 = loading 文案 + 按钮禁用（复用三态规范）；失败 = 内联错误 + 重试，**原文不清空**；超长 = 自动分段进度（第 x/y 段）。
- 用户可在本步切换到「原始全文」查看对照，可手动把误删内容补回净化结果。

### 4.2 净化规则（写入模板，删清单由模板描述，可随模板扩展）
删除（独立成行优先，正文内不误伤）：
- 书名 / 剧名 / 作者署名（出现在标题语境）；章/回/集/部标题行（`第X章/第X回/第X集/Chapter X` 等）；
- 目录、卷前语、序言/楔子之外的作者说明、公告、求票求关注；
- 网站残留：站点名、水印、翻页提示、本章字数、发布时间、链接；
- 备注/分析/附件信息等与剧情无关说明；正文括号内纯元信息注（"（本章完）""（待续）"）；
- 行内嵌的编者按/防采集乱码段。
保留：全部剧情正文（含对话、括号对话补充、内心独白、诗歌唱词等非叙事但属正文内容）；段落结构保留。

### 4.3 后端净化接口（草案）
- 新 Agent `source_cleaner`（编排 Agent，类比 `project_analyzer`：只做结构化处理，不创建生产任务），prompt 文件 `workspace/prompts/source-cleaner.md` + 可选多模板文件。
- `POST /dramas/clean-source`：入参 `{ content, template }`；超长自动分卷净化后顺序拼接；返回 `{ clean_text, removed: [{ category, snippet }] }`。
- `POST /dramas` 创建时：body 带 `clean_text`（可空）→ 显式幂等迁移新增列 `dramas.clean_text`（nullable TEXT；metadata 只作快照、不作正文真源）。
- `analyze-episodes` 入参 `content` 缺省时，后端读取优先级：`clean_text` 非空 → 用它；否则 `description`（兼容全部历史项目）。

## 5. 上下文分集设计（D5 落实，v0.2 核心新增）

### 5.1 问题
现有 `splitSourceIntoEpisodes` 把全文按长度等分（只在最近句号取齐）。它服务于"任意正文兜底可用"，但：① 不保证一集一个完整情节单元；② 原书自带的章/集结构信息（净化前）与集界无关（净化后标题行已删）——但**剧情的高潮/转折/场景切换点**需要 AI 判断，这正是"上下文"的价值。

### 5.2 方案：AI 建议段界 + 后端锚点切片（保持"正文不改写"）
1. 后端对**净化正文**做确定性切段（自然段/句号边界，同 `naturalBoundaries`），生成**段落索引**（每段 ≤ 前 24 字摘要随索引入 prompt，长文只注入段索引+摘要而非全文）。
2. `episode_planner`（`analyze-episodes`）返回增强结构：
   ```json
   {
     "recommended_count": 12,
     "episodes": [
       { "title": "…", "summary": "…",
         "para_start": 1, "para_end": 58 },
       { "title": "…", "summary": "…", "para_start": 59, "para_end": 121 }
     ]
   }
   ```
3. 后端 `splitSourceIntoEpisodes` 升级为 **anchor-based**：优先使用 AI 给出的 `para_start/para_end` 对应的文本切点（仍取最近自然边界对齐，保序、不重不漏）；AI 未返回段界、段号越界或超时 → **fallback 到现行等分**（能力降级不阻断，与"现有链路零行为变化"边界兼容）。
4. 每集正文仍来自原文切片，模型不改写——只是"切在哪"从长度均分改为剧情边界。

### 5.3 长文策略（借鉴 shuohao 的分卷摘要，在线化收敛）
- 全文 > 抽样阈值（建议约 4–6 万字）时：先跑一次**分卷摘要**（确定性按段落分批 → 让模型对每卷出 summary，复用现有 `sampleSourceContent` 思路扩展），摘要 + 段索引一起喂给 `episode_planner` 出集界；正文切片仍用真实正文，摘要仅用于定界。
- 集数建议继续使用现有 `defaultEpisodeCount`（每约 3500 字/集）作为 `recommended_count` 起点；AI 可基于剧情密度微调。限制 1–30 集不变。
- 一次 `analyze-episodes` 调用内完成（在线服务不暴露逐批会话）；调用超时/限流走既有 429 guard 与前端三态重试。

### 5.4 兼容与回归
- `episode_plan_drafts` 状态机、`from-plan` 建集路径、版本冲突检测、审阅确认流**全部不动**（建集唯一入口保持 `episode_plan_drafts → from-plan`，本需求不引入第二条建集路径）。
- 仅变化：`normalizeEpisodePlan` 校验 AI 段界合法性 + `splitSourceIntoEpisodes` 增加 anchor 参数与 fallback。
- 后端测试：等分旧用例全部保留（作为 fallback 断言）；新增 anchor 用例（含越界/缺失段界降级）。

### 5.5 与"详情页来源对照"的衔接（D2 落地）
- detail 剧本/原文区增加「原始全文 / 净化正文」切换（数据都在项目内，无网络请求）。
- 切换净化正文后分集草稿按 5.2 走；原始全文时行为=现状等分（历史项目无 `clean_text`，天然走此路径，零行为变化）。
- 允许用户"换模板重新净化并重新生成分集建议"（复用 detail 既有"全文已变化需重新生成"的 stale 守卫逻辑，仅来源变为 clean_text 版本变化）。

## 8. 验收标准（v0.2 更新）

1. 用用户上传的案例文本验证：净化后正文无书名/章集标题行/水印/字数/作者的话/备注；剧情段落连续不漏。
2. 案例文本「AI 分集草稿」：集界与剧情转折吻合（不再等分切穿高潮）；各集正文以剧情开头、不含标题行；同一次切分保序不漏字。
3. 创建向导可见「净化正文」独立步骤，可跳可回可重跑；切换模板重跑结果变化可见。
4. 设置 Prompts 新增「净化模板」类别：增删改模板保存即生效；新建向导下拉可选。
5. 原文与净化正文并存：detail 可切换对照；分集默认用净化正文；历史项目（无 clean_text）行为与现状完全一致。
6. AI 段界缺失/越界/超时 → 自动等分降级，不阻断分集。
7. 原有 70/70 前端结构测试 + 后端 analyze/split 旧用例全绿；新增净化/锚点切片用例。
