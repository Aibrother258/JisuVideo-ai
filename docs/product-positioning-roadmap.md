## 1. 产品定位

> **面向个人创作者和小型团队的 AI 短剧生产工作台：把小说、故事和剧本转成可审阅的分集方案、统一的人物场景资产、可执行分镜以及图片/视频生成任务，并保留每一步的修改、版本和回退。**

项目核心不是「一键成片」，而是：

> **从原文到第一个可用镜头，每一步可控、可修改、可追踪、可恢复。**

### 1.1 定位边界

| 是 | 不是 |
| --- | --- |
| 短剧/漫剧共用同一条叙事生产链（差异只在视觉风格与生成策略） | 重新拆出一级「视频类型」平台 |
| AI 短剧生产工作台 | UI 治理项目（那是已基本完成的工程专项，见 §5） |
| 让内容理解、分集、资产、生成可靠可复用的纵向闭环 | 什么都做的通用 AI 视频生成器 |

## 2. 当前阶段判断（2026-09-04）

主干能力已相当完整：

- 支持粘贴、TXT/MD、小说链接导入。
- AI 提炼标题、风格、画面比例。
- 全文分集、逐集编辑、批注、确认、重新拆分。
- 剧本改写、角色/场景/道具提取。
- 分镜拆解、图片提示词、视频提示词、MiniMax H3 提示词。
- 本地上传和资产库复用。
- 图片/视频任务、AutoDL、MiniMax、Seedance、整集拼接。
- 状态恢复、任务并发、分页、暗色主题、三态交互等工程基础。

**明显失衡**：最近大量 PR 在持续改善「工厂的装修和设备摆放」，核心生产结果缺少代表性长文的真实业务验收：

- 全文导入和 AI 分集完成了结构、接口、测试与页面验收，但真实长篇中文内容的 AI 分集质量尚未形成稳定基线。
- 批注重拆、长文本成本、分集边界准确率还没有真实数据。
- H3/AutoDL 已有部分真实验证，但「导入原文 → 成片」的完整代表项目尚未成为常态化回归样例。

**结论**：现在最重要的不是继续扩大功能面，也不是继续纯视觉优化，而是**把现有链路做成一个真正稳定、可复用的纵向闭环**。

## 4. 命名收敛：「原文整理与智能分集」

PR #58 发现的问题是对的，但「原文净化」不适合作为产品主线名称——它听起来像清理工具，且让用户担心 AI 删除正文。真正的用户价值是：

> **让系统更准确地理解长篇内容，并给出更可靠的分集边界。**

本阶段统一命名为 **「原文整理与智能分集」**。

| 层 | 命名 |
| --- | --- |
| 内部技术能力 | Source Preparation / Source Intelligence / Source Map / Episode Boundary Planning |
| 用户界面 | 检查原文 / AI 整理原文 / 查看整理结果 / 智能分集 |
| 不使用 | 「净化」作为主定位或强制步骤 |

更合理的流程：

```text
导入原文
  ↓
原文健康检查
  ├─ 内容干净：直接通过
  └─ 检测到章节号/广告/水印/重复段：建议整理，可预览、可跳过
  ↓
项目方案
  ↓
智能分集与逐集审阅
```

### 4.1 v0.4 修正方向（输入实施稿的要点）

- **质量边界（A 重定义）**：
  - AI 自动整理阶段：`removed.snippet` 必须能在原文中找到；删除区间不得重叠；自动整理结果必须能由原文与删除区间确定性复现；不允许 AI 顺手改写正文；章节标题先提取为结构锚点、不直接丢弃。
  - 用户人工编辑后：标记为「用户已编辑版本」，不再执行严格相减证明；保留原文、AI 整理稿、用户确认稿与差异记录；分集使用用户确认稿。
- **分集锚点**：不用单一易漂移的段落序号，组合使用稳定段落 ID、字符起止位置、段落内容哈希、段首短文本锚点，后端做模糊匹配与冲突提示；AI 建议边界，后端确定性切片；原文顺序不变、不漏字、不重复，越界/定位失败降级到现有算法，用户可审阅调整边界。
- **工程修正**（沿用 Hermes 评审）：`clean_text` 用 `LONGTEXT`；锚点 `backend/src/mastra/index.ts`；测试基线：前端结构测试当前 `148/148`，后端 analyze/split 旧用例回归、typecheck 与迁移测试单列执行；D 系列决策未获授权前不写「已拍板」。
- 候选参考：shuohao 报告 §5 的 A+C+H 组合（A 确定性质量门、C 模板规则分层、H 识别不到章节显式提示），H 并入 A。

> 以上要点仅作为 v0.4 实施需求 PR 的输入方向，不在本 PR 内立项。

## 7. 中期路线（未来 3–6 个月）

**主线一：内容理解质量**
- 原文版本管理。
- 章节、人物、事件、时间线结构图。
- 分集边界对比与历史版本。
- 分集结果质量统计。
- shuohao 策划包导入 Beta（**候选方向**——承接「短剧上游导入」，待单独立项后纳入排期；未立项前不作为正式路线承诺）。

**主线二：跨镜头一致性**
- 人物、场景、道具统一资产身份。
- 资产变更后自动提示受影响分镜。
- H3 提示词来源指纹与过期管理。
- 角色形象、服装、场景变化的版本管理。

**主线三：生产可靠性**
- 生成任务失败恢复。
- 重试与供应商切换。
- 每集成本、耗时、失败原因统计。
- 批量生成与人工确认门禁。
- 项目导入导出包。

## 8. 长期定位（6–12 个月）

长期发展为「AI 短剧生产操作台」，但仍**不做通用视频平台**。只扩展四类能力：

1. **叙事理解**：原文、人物、事件、分集、剧本。
2. **资产一致性**：人物、场景、道具、视觉风格与版本。
3. **生成执行**：图片、视频、音频供应商适配与任务恢复。
4. **制片协作**：审阅、批注、版本、成本、导出与团队协作。

未来若重新支持口播、Vlog、产品介绍，应等短剧主线被真实用户跑通后，以「预设或轻量工作流」验证，而不是重建六类型平台。

## 9. 核心指标

**北极星指标**：

> **从导入原文到获得第一个可用分镜视频所需时间。**

同时记录（与真实基线阶段同步启动采集）：

- AI 分集后用户调整边界的比例。
- 误删正文与人工恢复比例。
- 分镜一次确认通过率。
- 人物/场景跨镜头一致性问题数量。
- 视频任务首次成功率。
- 失败任务恢复成功率。
- 单集成本与耗时。
- 从项目创建到整集导出的完成率。

> 没有这些数据，后续再多 PR 也难以判断是在改善产品，还是只在增加代码和界面。
