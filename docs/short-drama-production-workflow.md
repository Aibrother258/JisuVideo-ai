## 1. 行业全景：三类剧种定义与市场定位

| 维度 | 短剧（竖屏微短剧） | 漫剧（动态漫） | 真人剧（长剧） |
|---|---|---|---|
| 单集时长 | 1–3 分钟 | 1–3 分钟 | 30–45 分钟 |
| 总集数 | 60–100 集（首集免费引流） | 50–80 集 | 12–40 集 |
| 画面比例 | 竖屏 9:16（移动端投流） | 竖屏 9:16 或横屏 | 横屏 16:9 |
| 内容形态 | 真人实拍 / AI 生成 | 静态漫画 + 运镜 + 配音 | 真人实拍 |
| 制作周期 | 单剧 15–30 天 | 单剧 7–15 天（AI 最快） | 单剧 3–6 个月 |
| 单集成本 | 数千元 – 数万元 | 数百元 – 数千元 | 数十万元起 |
| 核心商业模式 | 信息流投流 + 付费解锁/广告 | 平台分成 + 投流 | 平台采购 / 会员 |
| 核心成功要素 | 前三秒钩子、强反转、情绪浓度 | 画面质量、配音节奏 | 剧本、演员、制作水准 |

**行业共识：**
- 短剧是「数据产品」而非「艺术作品」——剧本结构（每集结尾留钩子、3 秒内建立冲突）与投流 ROI 决定生死；
- 漫剧是成本最低的 AI 内容形态，天然适合 AIGC 全流程自动化（本平台最贴合的场景）；
- 真人剧重资产，AI 目前主要介入剧本、分镜、后期辅助，拍摄环节仍需人。

## 2. 行业主流通用生产链路（七阶段）

无论哪类剧种，行业通用链路都是以下七个阶段。区别仅在于各阶段由「人」还是「AI」完成。

### 阶段 1：选题立项（调研 → 决策）

- 拉取抖音/快手/ReelShort 等平台短剧热榜，分析爆款题材（赘婿、战神、逆袭、复仇、甜宠、穿越、悬疑…）；
- 确定目标人群（下沉市场女性向 / 男频爽文 / 泛年龄喜剧…）；
- 用 AI 辅助：让大模型分析热榜标题与梗概，提炼「题材 + 情绪钩子 + 投放卖点」；
- 决策输出：剧名候选、题材方向、目标集数、单集预算、投放渠道。

> 平台对应能力：`project_analyzer`（项目方案提炼）会给出剧名候选、风格候选、画面比例建议与内容摘要。

### 阶段 2：剧本与策划（网文 IP → 剧本 → 卡点设计）

- **素材获取**：购买/授权网文小说，或直接用原创短篇故事；
- **改编**：小说 → 短剧剧本（每场景 30–60 秒，动作描写 + 对白，去掉心理描写）；
- **拆集策划**：按总集数切分剧情，每集结尾设计钩子（悬念、反转、冲突爆发）；
- **卡点设计**：第 3 秒钩子（前情冲突）、第 30 秒小反转、结尾强钩子；
- 台词密度：约 4.5 字/秒 语速 + 表演余量，避免台词超载。

> 平台对应能力：`script_rewriter`（剧本改写）、`episode_planner`（全文拆集策划）。

### 阶段 3：前期筹备（资产与物料）

- **角色**：确定主角/配角名单，设计外貌（年龄感、五官、体态、气质）与妆造（发型、服装、妆面）；
- **场景**：按「地点 + 时间段」建立场景清单（内/外景、年代质感、光影氛围）；
- **道具**：只保留「推动剧情 + 需要固定外观」的关键道具（凶器、信物、文件等），一集 0–3 个为宜；
- 真人剧额外：演员试镜、服化道、场地、摄影灯光、分镜脚本（导演表）。

> 平台对应能力：`extractor`（角色/场景/道具智能提取与去重）、`prompt_generator`（生图提示词）。

### 阶段 4：拍摄 / 内容生成

**真人短剧（传统）：**
- 按分镜表拍摄，竖屏构图，现场收音或后期配音；
- 常用「单机位多机位复用」压成本，一天拍 20–40 场戏。

**漫剧 / AI 生成（本平台主路径）：**
- 生图：按角色三视图 / 场景固定视角 / 道具白底单品生成静态图；
- 视频：文生视频（T2VA）/ 图生视频（I2VA）/ 参考图驱动（Ref2VA）将静态镜头动起来；
- 一个分镜段落 = 一个视频生成任务（8–15 秒，内部含 2–4 个子镜头）。

### 阶段 5：后期制作

- **剪辑**：按分镜段落拼接，保证节奏与卡点；
- **配音**：AI 语音（TTS）或真人配音，对白逐句对齐；
- **字幕**：自动识别/按剧本打轴，竖屏大字、关键词变色；
- **音乐音效**：背景音乐、音效、转场音；
- **调色**：统一影调，漫画感/电影感；
- **合成导出**：单镜头合成（画面+字幕+音轨）→ 整集拼接 → 多集成片（行业后期工序，平台侧覆盖范围见下行）。

> 平台对应能力：FFmpeg 按序拼接已生成的镜头视频（整集拼接导出）。单镜头的字幕/音轨合成、配音当前**未实现**，属后续规划或需在外部后期完成。

### 阶段 6：质检与成片

- 逐集检查：画面、字幕错别字、配音对齐、音量、卡点是否生效；
- 合规审查：色情、暴力、价值观、版权（音乐/字体/素材授权）；
- 生成多版本封面（海报帧）+ 前 3 秒引流片段（用于投流）。

### 阶段 7：投放与数据复盘

- 信息流投放（抖音千川 / 快手磁力 / 海外 Meta、TikTok）；
- 核心指标：前 3 秒完播率、第 1 集转付费率、ROI、人均解锁集数；
- 数据回流 → 决定是否加更、续集、改剧本走向（短剧特有的「边播边改」）。

## 3. 三类剧种的差异化流程

### 3.1 真人短剧（行业标准流程）

```
选题调研 → 剧本（7天）→ 选角/筹备（3-5天）→ 拍摄（10-20天）→ 后期（7-10天）→ 投放
```

关键岗位：编剧、导演、制片、演员、摄影、灯光、服化道、剪辑、投手。

- 剧本按「每 60 秒一个冲突，每集一个反转钩子」编写；
- 拍摄追求单机位效率，竖屏构图（人物居中、近景为主）；
- 投流预算通常是制作预算的数倍，「投流定生死」。

### 3.2 漫剧 / 动态漫（AI 首选形态）

```
选文 → 拆集 → 剧本 → 角色/场景生图 → 分镜 → 图生视频(运镜) → 配音+字幕 → 合成
```

关键岗位：AI 美术 + AI 视频 + 配音（可全自动化）。

- 人物形象一次生成、全剧复用（保持一致性是成败关键，依赖参考图/角色三视图）；
- 靠「运镜 + 配音 + 音效」让静态画面有动态感，因此视频提示词的质量比画面更重要；
- 单集成本可压到几百元，日更 2–3 集可行。

### 3.3 真人剧（长剧，重资产）

```
立项 → 剧本开发(数月) → 报审/备案 → 建组 → 拍摄(2-4个月) → 后期 → 发行
```

- AI 目前用于：剧本评估、分镜脚本、概念图、后期辅助（修复、调色）；
- 全流程周期长、资金门槛高，不适合个人/小团队全流程 AI 化。

### 3.4 三类剧种流程对照表

| 环节 | 真人短剧 | 漫剧（AI） | 真人剧 |
|---|---|---|---|
| 剧本 | AI 辅助改编 | AI 全自动 | 专业编剧 |
| 角色 | 真人演员 | AI 生图 + 一致性约束 | 试镜选角 |
| 分镜 | 导演分镜表 | AI 拆解 + 视频提示词 | 专业分镜师 |
| 内容生产 | 实拍 | 生图 + 图/文生视频 | 实拍 |
| 后期 | 人工剪辑 | FFmpeg 自动合成 | 专业后期团队 |
| 投放 | 投手 + 数据 | 投手 + 数据 | 平台发行 |

## 4. 本平台 AI 自动化流水线

### 4.1 平台能力概览

- **运行时**：Node.js 20+ / Hono / Drizzle ORM / MySQL 8；前端 Nuxt 3。
- **AI 模型层**（Web「设置」页配置，支持厂商切换与连通性测试）：
  - 文本：OpenAI（兼容接口）/ Gemini / 火山引擎；
  - 图片：OpenAI / Gemini / 火山引擎；
  - 视频：火山 Seedance 2.0（标准/Fast/Mini）、MiniMax H3（官方 T2VA/I2VA/Ref2VA）、AutoDL（ComfyUI H3 工作流）。
- **Agent 层**（Mastra；各 Agent 提示词存于 `backend/workspace/prompts/<agent_type>.md`，技能存于 `backend/workspace/skills/` 的 `SKILL.md`，文本/图片/视频厂商配置在 Web「设置」页管理）：

| Agent | 对应行业环节 | 职责 |
|---|---|---|
| `project_analyzer` | 选题立项 | 提炼剧名候选、风格候选、画面比例建议、内容摘要 |
| `episode_planner` | 拆集策划 | 按全文长度/节奏推荐集数，规划每集标题与内容重点 |
| `script_rewriter` | 剧本改编 | 小说 → 格式化短剧剧本（场景头/动作/对白） |
| `extractor` | 资产提取 | 角色/场景/道具提取，与项目已有数据智能去重 |
| `prompt_generator` | 生图/视频提示词 | 角色/场景/道具最终提示词 + 分镜视频提示词 |
| `storyboard_breaker` | 分镜拆解 | 剧本 → 分镜段落（8–15s/段，含子镜头与台词） |
| `minimax_h3_prompt_generator` | 视频提示词（H3） | 中文分镜提示词 → MiniMax H3 英文结构化提示词 |

### 4.2 流水线逐环节（与行业阶段对照）

```
行业阶段1选题  ──►  行业阶段2剧本  ──►  行业阶段3筹备  ──►  行业阶段4生成  ──►  行业阶段5后期
    │                   │                   │                   │                   │
导入素材        项目方案提炼         剧本改写           资产提取        分镜拆解
(链接/文本)     project_analyzer    script_rewriter    extractor      storyboard_breaker
    │                                                                    │
拆集策划  ──►                                                          视频提示词
episode_planner                                                          prompt_generator
                                                                        / minimax_h3
                                                                            │
                                                                       视频生成
                                                                       (Seedance/H3)
                                                                            │
                                                                      合成与导出(FFmpeg)
```

#### 环节 A：导入素材
- 支持小说链接（自动抓取，带 SSRF 防护：仅公网、限 6MB/20 万字符）或直接粘贴 TXT/MD 文本；
- 对应行业「获取网文 IP」。

#### 环节 B：项目方案提炼（`project_analyzer`）
- 输入：原文/梗概；
- 输出 JSON：4 个剧名候选、恰好 3 个风格候选（含风格 key 与英文生图提示词）、9:16/16:9/1:1 画面比例适配排序、60–120 字内容摘要；
- 对应行业「选题立项」。

#### 环节 C：全文拆集策划（`episode_planner`）
- 按全文长度、叙事节奏、冲突密度推荐集数（1–30 集），或按指定集数规划；
- 每集输出标题 + 摘要（主要事件、冲突推进、结尾钩子），顺序覆盖全文；
- 对应行业「拆集与卡点设计」。

#### 环节 D：剧本改写（`script_rewriter`）
- 小说 → 格式化剧本：`## S编号 | 内/外景 · 地点 | 时间段` + 动作段落 + `角色名：（状态）台词`；
- 每场景 30–60 秒，符合短剧节奏；
- 对应行业「网文改编剧本」。

#### 环节 E：资产提取（`extractor`）
- 读取本集剧本 → 提取角色（外貌 + 妆造两字段）、场景（描述 + 光影两字段）、关键道具（0–3 个）；
- 按名字/「地点+时间段」与项目已有资产去重合并；
- 对应行业「角色/场景/道具筹备」。

#### 环节 F：图片提示词与生图（`prompt_generator`）
- 角色/场景/道具最终提示词按 Skill 规范生成（角色三视图 / 场景固定视角 / 道具白底单品）；
- 调用图片厂商生成静态图，自动产出缩略图与海报帧；
- 对应行业「服化道与场景设计」。

#### 环节 G：分镜拆解（`storyboard_breaker`）
- 剧本 → 分镜段落：识别叙事节拍强制切段，每段 8–15 秒、含 2–4 个子镜头、绑定角色/场景/道具；
- 时长硬约束：目标总时长 = 字数 ÷ 500字/分；台词下限 = 台词字数 ÷ 4.5字/秒 + 2 秒余量；
- 对应行业「导演分镜表」。

#### 环节 H：视频提示词（`prompt_generator` / `minimax_h3_prompt_generator`）
- 中文视频提示词：按 3 秒一段分行的结构化描述，`@角色名/@场景名` 自动映射参考图；
- H3 专用：改写为英文结构化 T2VA / I2VA / Ref2VA 提示词，对白/旁白保留原文；
- 对应行业「镜头脚本与 AI 提示词工程」。

#### 环节 I：视频生成
- Seedance 2.0（标准 / Fast / Mini）文生视频；
- MiniMax H3：T2VA（文生视频）、I2VA（图生视频）、Ref2VA（参考图一致性，用于角色保持一致）；
- AutoDL ComfyUI 工作流（`minimax_h3_image_audio_to_video_v2_15s`）；
- 支持参考图片、参考视频、参考音频（口型/动作/音色）资产；
- 对应行业「拍摄」。

#### 环节 J：整集拼接导出（FFmpeg）
- 整集拼接：按分镜顺序将已生成的镜头视频拼接导出；音频仅透传镜头视频自带的音轨，不生成/合成新音轨；
- 单镜头的字幕烧录、TTS 配音与音轨合成**未实现**，属后续规划，需在外部后期完成；
- 对应行业「剪辑」中的拼接环节（「字幕、合成」部分属后续规划）。

## 5. 从 0 到 1 实操手册

> 以「导入一部小说 → 自动产出漫剧/短剧全集分镜与视频」为例，全部在 Web 界面操作。

### 准备
1. 部署启动（开发模式或 Docker，见根目录 README）；
2. 打开「设置 → AI 服务」页，配置文本/图片/视频三类 AI 服务（用「手动模板」按服务类型添加推荐配置，再做连通性测试）；
3. 准备小说原文（TXT/MD 文件，或可公开访问的小说链接）。

### 操作步骤
1. **新建剧集**：填写剧名（可先用 AI 提炼的候选名）、选择风格预设与画面比例（短剧选 9:16）；
2. **导入原文**：上传文件或粘贴链接 → 系统抓取/读取原文；
3. **项目方案提炼**：点击分析，得到剧名/风格/比例建议，可一键应用；
4. **拆集策划**：点击生成分集方案，确认集数、每集标题与钩子摘要；
5. **批量建集**：从分集方案一键创建各集；
6. **剧本改写**：逐集（或批处理）将原文段落改写为格式化剧本；
7. **资产提取**：提取本集角色/场景/道具 → 检查去重结果；
8. **生成资产图**：对角色/场景/道具生成最终提示词 → 调用生图 → 素材库查看缩略图，不满意的可手动重生成或上传替换；
9. **分镜拆解**：生成整集分镜段落（8–15 秒/段）；
10. **生成视频提示词**：逐段生成中文视频提示词（或直接生成 H3 提示词）；
11. **生成视频**：选择厂商与模式（漫剧推荐 H3 I2VA/Ref2VA 保持角色一致），批量生成分镜视频，跟踪任务进度；
12. **合成导出**：校验各镜头视频文件存在 → 按序整集拼接 → 导出成片。字幕烧录/音轨合成当前未实现（属后续规划），如成片需要字幕配音，请在外部后期软件处理后再上传。

### 交付质检清单
- [ ] 首 3 秒有冲突或钩子
- [ ] 每集结尾有强钩子
- [ ] 角色形象跨镜头一致（必要时用参考图/Ref2VA 重新生成）
- [ ] 字幕无错别字、无越界（若成片经外部后期添加了字幕）
- [ ] 配音/台词节奏自然、不超时长（若成片经外部后期添加了配音）
- [ ] 关键道具在特写镜头中外观一致
- [ ] 片头/片尾与平台规范一致（版权音乐、字体授权）

## 6. 质量与合规要点

- **内容合规**：建议创作者规避色情、暴力、涉政等红线题材，并遵守当地法律法规与投放平台发布规范；当前系统提供的审核主要为技术防滥用（SSRF、体积/类型限制等），不构成对内容合规性的自动审查或承诺；
- **版权合规**：小说需有改编授权；AI 生成内容注意平台服务条款；音乐/字体需商用授权；
- **数据合规**：AI 服务 Key 入库管理，不在代码/配置中明文扩散；素材上传有体积与类型限制；
- **技术防滥用**：小说导入有 SSRF 防护（禁内网/本地链接）、体积限制；Agent 请求有 request guard 层。

## 8. 常见问题与优化建议

### 画面一致性差（漫剧最常见痛点）
- 优先用**参考图（I2VA/Ref2VA）**生成视频，而不要裸文生视频；
- 角色三视图提示词、场景固定视角提示词要足够具体（外貌 + 妆造字段不要简略）；
- 同一角色尽量复用一个固定的形象图，避免每次重新生图。

### 视频生成慢 / 成本高
- 过渡段（赶路/空镜）用 8–10 秒短段，爆点段才用 15 秒；
- 批量任务按厂商分档（Fast 档用于预览，标准档用于成片）；
- 失败的镜头单独重试，不要整集重新生成。

### 台词超时长 / 配音对不上
- 遵循「台词字数 ÷ 4.5字/秒 + 2 秒余量」规则，装不下的台词拆到下一段落；
- 视频提示词中台词必须与剧本一致，不要「创作」新台词。

### 字幕错位 / 乱码
- 全程使用 UTF-8 编码（团队规则：涉及中文文本一律 UTF-8，见 `CLAUDE.md`）；
- 合成后抽帧抽查，重点是竖屏大字安全区。

### 投放后完播率低
- 反查「第 3 秒钩子」是否成立、前 1 集是否信息过密；
- 用 `episode_planner` 调整每集摘要的「结尾钩子」，优先强化强反转场景的分镜节奏。
